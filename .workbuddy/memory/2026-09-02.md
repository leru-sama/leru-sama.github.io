**转换要点（复用价值高）**
- 原 HTML 全部 36 个公式都是块级 `\[...\]`，无行内公式。
- 公式必须用 `{{< eq >}}` 短代码（`{{< >}}` 不让 Goldmark 处理）。若直接写进 Markdown，
  `q'_{2i} \\ q'_{2i+1}` 这类会被误判成 `<em>` 斜体。
- 公式定界符用 `$$…$$` 而不是 `\[…\]`：模板里写反斜杠易踩转义坑，且 `$$` 是 KaTeX 默认分隔符。
- `<br>` 需转成 Markdown 硬换行（行尾两空格），否则段落被挤成一行。
- `<code>` 内含 `<sub>` 时不能用反引号（尖括号会被转义），改用裸 `<code>`。
- 以标点结尾的强调：`**加粗。**后续文字` 中闭合 `**` 不满足 CommonMark 右边界规则，
  **不会**渲染成粗体。解决办法：内容末字符为标点（unicodedata P*）时改用裸 `<strong>`/`<em>`，
  裸 HTML 标签内部的 Markdown 仍会被正常处理（但整个段落不能被 `<p>` 包住，否则变 HTML 块）。
- 提示框用 `{{% admonition %}}`（要渲染内部 Markdown），`{{< >}}` 不会渲染。
- SVG 图用 `{{< figure src="figN.svg" alt="…" caption="…" >}}`，必须显式给 alt，
  否则 shortcode 会把整段 caption 塞进 alt。
- 交互式计算器：HTML + 配套 JS 一起放进 `{{< rawhtml >}}`。

**踩坑**
- Edit 工具对含转义序列（`\n`、`\x00` 等）的 old_string 会**静默失败**（报 success 但文件未改）。
  改文件这类内容时改用 Python 脚本打补丁并 assert 匹配数。
- 校验方法：把源 HTML 与生成页面都剥掉标签/解码实体后做逐段子串比对，
  本次 129 段中 128 段完全一致（唯一差异是副标题变成了 description）。
